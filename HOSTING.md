# Развёртывание LFR Store Bot

## Что требуется

- Node.js 24 (минимум 22.12) либо Docker.
- Один постоянно работающий worker с исходящим доступом к Discord.
- Постоянный локальный диск для SQLite.
- Запуск только одной реплики бота.

Боту не нужен входящий HTTP-порт. Хостинг, который требует web health check или выключает worker при отсутствии запросов, для него не подходит без отдельного always-on worker.

## Переменные окружения

Создайте их в панели хостинга по `.env.example`:

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DISCORD_TOKEN` или `BOT_TOKEN` | да | Токен Discord-бота; `BOT_TOKEN` может автоматически создавать хостинг |
| `APPLICATION_ID` | для регистрации команд | ID приложения Discord |
| `GUILD_ID` | да | ID единственного целевого сервера |
| `VOICE_CHANNEL_ID` | нет | Голосовой канал постоянного подключения |
| `DATABASE_PATH` | да на хостинге | Рекомендуется `/app/data/shop.sqlite` |
| `CONFIG_PATH` | да в Docker | `/app/config/shop.json` |
| `LOCK_PATH` | рекомендуется в Docker | Временный путь `/tmp/lfr-store-bot.lock` |
| `SHOP_NAME` и контакты | нет | Переопределяют непустыми значениями `config/shop.json` |

Никогда не добавляйте рабочий токен в `.env.example`, `Dockerfile`, Compose или настройки GitHub Actions. Секрет хранится только в `.env` локально или в secret variables хостинга.

## Docker

```sh
cp .env.example .env
# Заполните обязательные значения
docker compose build
docker compose up -d
docker compose logs -f bot
```

Compose монтирует локальную папку `data` в `/app/data`. Для обновления:

```sh
docker compose build --pull
docker compose up -d
```

## Хостинг без Docker

Если панель хостинга запрашивает команды отдельно, укажите:

```sh
Install: npm ci
Build: npm run build
Start: npm start
```

Этап Build можно оставить пустым: `npm start` запускает `src/index.ts` через production-зависимость `tsx` и не требует каталога `dist`. Это поддерживает простые панели хостинга, которые выполняют только установку пакетов и Start-команду.

Если хостинг запрашивает поле **«Главный файл»**, **«Файл запуска»** или **«Entry point»** и сам добавляет команду `node`, укажите только:

```text
index.js
```

Не вписывайте в такое поле `npm start`, `tsx src/index.ts` или `node index.js`: панель воспримет всю строку как имя файла.

Для уже созданной карточки хостинга, которая сохранила ошибочное значение `tsx src/index.ts` и не позволяет его изменить, в репозитории оставлен совместимый путь `tsx src/index.ts`. Он перенаправляет запуск на настоящий `src/index.ts`. Для новых карточек используйте обычный `index.js`.

Подключите постоянный диск к каталогу, указанному в `DATABASE_PATH`. Не используйте ephemeral filesystem: после перезапуска пропадут привязки каналов, ID панелей, каталог и заказы. `LOCK_PATH` держите во временном каталоге конкретного контейнера, например `/tmp/lfr-store-bot.lock`.

## Перенос действующего магазина

1. Остановите локальный процесс бота. Одновременная работа локальной и серверной копии запрещена.
2. Скопируйте `data/shop.sqlite` в каталог постоянного диска хостинга. При остановленном процессе WAL уже закрывается штатно; если рядом остались `shop.sqlite-wal` и `shop.sqlite-shm`, перенесите их вместе либо сделайте согласованную резервную копию SQLite.
3. Добавьте переменные окружения на хостинге.
4. Запустите ровно одну реплику.
5. Проверьте журнал запуска и выполните `/diagnostics`.
6. Запустите `/panel name:all`, чтобы применить последнюю версию оформления к существующим сообщениям.

`!shop-setup` после переноса рабочей БД не требуется. Для совершенно новой БД сначала выполните `!shop-setup preview`, затем `!shop-setup` в личных сообщениях боту.

## Slash-команды

Перед первым запуском приложения или после изменения `src/commands.ts` выполните один раз:

```sh
npm run register
```

Регистрацию можно выполнить локально с теми же `DISCORD_TOKEN`, `APPLICATION_ID` и `GUILD_ID`. Она не должна запускаться при каждом старте worker.

## Проверка перед публикацией

```sh
npm ci
npm run deploy:check
git status --ignored --short
```

В Git не должны попадать `.env`, `data/shop.sqlite*`, журналы, `.tools`, `node_modules` и `dist`.
