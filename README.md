# LFR STORE — Discord-бот магазина

Первая версия на TypeScript, Node.js 20+, discord.js 14.27.0 и SQLite (`better-sqlite3`). Проект создан в пустой рабочей папке. Все четыре предоставленных PNG скопированы без изменения изображения. Публичные панели используют Components V2, фиолетовый акцент `#793CFF`, крупные заголовки, Media Gallery и нативные разделители.

## Где менять информационную панель

Основной файл — **`config/shop.json`**. Измените его, затем выполните `/panel name:information`; для согласованного обновления правил и остальных панелей — `/panel name:all`.

| Что менять | Настройка |
| --- | --- |
| Название | `SHOP_NAME` |
| Discord | `DISCORD_URL` — пустая строка скрывает строку |
| Telegram | `TELEGRAM_URL` — пустая строка скрывает строку |
| Контакт сотрудничества | `PARTNERSHIP_CONTACT` — текст, ссылка или `<@ID>`; пустая строка скрывает строку |
| Год начала работы | `START_YEAR` — например `"2020"`; по умолчанию не указан |
| Приветствие и блоки информации | `information.*` |
| Обычное время выдачи | `delivery.usual` |
| Срок Nitro и подписок | `delivery.subscriptions` |
| Уведомление о задержке | `delivery.delay` |
| Гарантия, видео, возврат, нарушение правил | `delivery.guarantee`, `video`, `refund`, `penalty` |
| Баннер информации | `appearance.banners.information`: `assets/welcome.png` |
| Баннер правил | `appearance.banners.rules`: `assets/rules.png` |
| Баннер тикетов | `appearance.banners.tickets`: `assets/tickets.png` |
| Баннер товаров | `appearance.banners.products`: `assets/products.png` |
| Цвет акцента | `appearance.accent` |
| Восемь правил | `rules.items`, заголовки — `rules.title`, `intro`, `itemTitle` |
| Остальные панели | `texts.*` |
| Имена каналов, категорий и эмодзи | `structure.*` |
| Названия и цвета ролей | `roles.*` |

Названия, ссылки, контакт и год также можно задать в `.env`: **непустое значение `.env` имеет приоритет над JSON**. Для их изменения в `.env` перезапустите процесс. JSON перечитывается при `/panel`; для немедленного применения настроек структуры выполните настройку сервера заново. Неверные настройки и слишком длинные панели отклоняются до публикации.

Чтобы заменить баннер, замените PNG по текущему пути либо укажите новый путь относительно корня проекта. Выполните `/panel name:information`. Бот редактирует сохранённое сообщение, удаляет предыдущее вложение и загружает новый файл. Можно задать `""`, чтобы показывать панель без баннера. Изображение отправляется целиком, без программного кадрирования; отображение и ширину определяет Discord.

Тексты поддерживают переменные `{SHOP_NAME}`, `{PRODUCTS_CHANNEL}`, `{TICKETS_CHANNEL}`, `{RULES_CHANNEL}`, `{SELLER_ROLE}`, `{USUAL_DELIVERY}`, `{SUBSCRIPTIONS_DELIVERY}`, `{GUARANTEE}`, `{DELAY}`, `{VIDEO}`, `{REFUND}`, `{PENALTY}`, `{DISCORD_URL}`, `{TELEGRAM_URL}`, `{PARTNERSHIP_CONTACT}`, `{START_YEAR}`. Упоминания формируются из ID в SQLite. Массовые уведомления выключены. В заголовке отдельного правила доступна `{NUMBER}`.

Условия по умолчанию — информационный текст. Они не запускают автоматические наказания, списание денег, возвраты или выдачу. **5–15 минут — обычное время выдачи**, Nitro и подписки — отдельный срок после подтверждения оплаты. Карточки используют общие `delivery.*`; уже подтверждённый заказ хранит снимок условий.

## Установка и запуск

`VOICE_CHANNEL_ID` в `.env` задаёт голосовой канал, в котором бот постоянно находится. Бот подключается при запуске и автоматически возвращается после отключения или перемещения. Пустое значение отключает эту функцию.

1. Установите Node.js **20 или новее**. В `.nvmrc` указан major 20. В этой рабочей папке для локальной проверки также находится локальный Node в `.tools/`; это служебная папка, она не нужна при обычной установке Node.
2. В каталоге проекта:

   ```sh
   npm ci
   cp .env.example .env
   ```

3. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение и официального бота. Заполните в `.env`:

   ```dotenv
   DISCORD_TOKEN=токен_бота
   APPLICATION_ID=id_приложения
   GUILD_ID=id_целевого_сервера
   ```

4. В настройках Bot включите **Server Members Intent** и **Message Content Intent**. Используются Gateway intents: Guilds, GuildMembers, GuildMessages, MessageContent, DirectMessages. DM поддерживаются через `Partials.Channel`; partial сообщения нужны для событий удаления.
5. Пригласите бота через OAuth2 URL Generator со scopes `bot` и `applications.commands`. Для первоначальной настройки временно выдайте **Administrator**. Поднимите роль бота выше ролей магазина. Владелец магазина с ID `689455809612349463` должен состоять на сервере.
6. Зарегистрируйте команды и запустите:

   ```sh
   npm run register
   npm run build
   npm start
   ```

   Для разработки: `npm run dev`. Запускать команды нужно **из корня проекта**. Если Node ещё не добавлен в PATH на этом Mac, перед командами выполните:

   ```sh
   export PATH="$PWD/.tools/node-v24.20.0-darwin-arm64/bin:$PATH"
   ```

7. С аккаунта **689455809612349463** отправьте боту **в личные сообщения**:

   ```text
   !shop-setup
   ```

   Команда создаст роли, категории, каналы, назначит владельцу Admin/Seller при первом обычном запуске, добавит людям роль «Участник», опубликует панели и запустит статистику. Отчёт придёт в тот же DM. В публичной справке slash-команд этой команды нет.

Другой Discord ID, включая администратора или владельца сервера, не может запускать настройку. Команда в серверном канале игнорируется. Аргументы не позволяют заменить целевой сервер или ID владельца.

## GitHub и хостинг

Проект готов к публикации без локальных секретов и рабочих данных. `.env`, SQLite, WAL/SHM, PID lock, журналы, `node_modules`, `dist` и локальная `.tools` исключены из Git и Docker build context. Перед каждым push выполните:

```sh
npm run deploy:check
```

GitHub Actions запускает ту же проверку на Node.js 20. Для Docker подготовлены `Dockerfile` и `compose.yaml`. Локальный запуск production-образа:

```sh
cp .env.example .env
# Заполните DISCORD_TOKEN, APPLICATION_ID и GUILD_ID
docker compose up -d --build
docker compose logs -f bot
```

На хостинге используйте **один постоянно работающий worker**, а не веб-сервис и не несколько реплик. Подключите постоянный диск к `/app/data`, задайте `DATABASE_PATH=/app/data/shop.sqlite`, `CONFIG_PATH=/app/config/shop.json` и переменные из `.env.example`. Команды Discord регистрируются один раз через `npm run register`; после обычного обновления кода повторная регистрация не требуется.

Для Node.js-хостинга без Docker: установка — `npm ci`, сборка — необязательно либо `npm run build`, запуск — `npm start`. Start-команда запускает TypeScript из `src` и поэтому не зависит от наличия `dist`.

Для переноса уже настроенного магазина сначала остановите локального бота и скопируйте `data/shop.sqlite` на постоянный диск хостинга. Не добавляйте базу в Git: в ней находятся ID ресурсов, заказы, тикеты и история. Без переноса БД хостинг увидит магазин как новую установку. Подробная инструкция находится в [`HOSTING.md`](HOSTING.md).

## Настройка сервера и восстановление

- `!shop-setup preview` — проверка прав и план без изменений Discord.
- `!shop-setup status` — сохранённые ресурсы, последний отчёт, проверенные значения статистики и время обновления (Unix ms).
- `!shop-setup repair` — восстановление управляемых ресурсов; вручную снятые Admin/Seller у владельца не выдаются повторно.
- Повторный `!shop-setup` обновляет управляемую структуру и панели по ID. Назначенные чужие роли и посторонние каналы не удаляются.

В `bindings` можно заранее указать точные ID уже существующих ресурсов: `"roles.seller": "..."`, `"channels.information": "..."`, `"categories.tickets": "..."`. Это явное разрешение боту привести указанный ресурс к настройкам проекта. Имя ресурса само по себе не является привязкой. Не привязывайте интеграционные роли и `@everyone`.

Результаты каждого шага сохраняются в `resources` и `setupReport`. До создания ресурса записывается уникальная операция, передаваемая в audit reason. Если процесс прервался между Discord API и сохранением ID, повторный запуск ищет операцию в аудите. Если результат нельзя надёжно установить, бот остановится с указанием операции: проверьте аудит и заполните её ID в `bindings`. Он не создаёт второй ресурс вслепую. Discord хранит аудит ограниченное время; автоматический поиск рассматривает последние 100 записей нужного типа.

Роль бота должна находиться выше ролей магазина. Несколько ролей могут иметь одинаковую числовую позицию Discord; это само по себе не означает недостаток прав. Бот рассчитывает полный порядок с учётом ID, меняет местами только роли магазина и сохраняет места своей роли и посторонних ролей. После запроса порядок проверяется повторным чтением Discord API. Уже правильный порядок повторно не отправляется. Если конкретная роль действительно выше роли бота, отчёт укажет её имя. Созданные ID остаются в БД; после исправления повторите `!shop-setup`.

Если ресурса нет по сохранённому ID, `repair` создаёт его заново. Ошибка доступа не считается отсутствием ресурса. Если утрачен ID сообщения панели, бот ищет своё сообщение по служебному ID компонента (без видимой технической подписи). Если прежний канал панели удалён, бот подтверждает это через Discord API и публикует панель в восстановленном канале с новым ID сообщения. Ошибка доступа не считается удалением. Если прежний канал ещё существует, автоматический перенос останавливается, чтобы избежать двух публичных копий.

Бот рассчитан на **один процесс и один целевой сервер**. Локальный PID lock предотвращает запуск второго процесса с той же БД; очереди сериализуют настройку и изменения тикетов. Не запускайте несколько реплик на сетевой файловой системе. Discord REST обрабатывает очередь и rate limits; задачи уведомлений остаются в SQLite после сбоя.

## Права ролей

Порядок: **Admin → Seller → Developer → Manager → Sponsor → Partner → Diamond → Golden → Bronze → Участник**. Управляемая роль бота должна быть выше.

| Роль | Фактические глобальные permissions роли | Доступы, выдаваемые overwrites / ботом |
| --- | --- | --- |
| Admin | Administrator (`8`) | Администрирование магазина и каналов. `hoist=false`, `mentionable=false`, нейтральный цвет. Команда настройки всё равно только для точного ID владельца |
| Seller | `0` | Все тикеты и архивы, финансовые кнопки; каталог, цены и наличие; заявки розыгрышей; публикации в новостях, товарах, розыгрышах, халяве и кейсах |
| Developer | `0` | Технический журнал, журнал ролей, `/diagnostics` |
| Manager | ModerateMembers (`1099511627776`) | Все тикеты и архивы без финансовых действий; ManageMessages в чатах и отзывах; MoveMembers, MuteMembers, DeafenMembers в голосовых комнатах; модерационные журналы |
| Sponsor | `0` | Общедоступные каналы |
| Partner | `0` | Общедоступные каналы |
| Diamond | `0` | Общедоступные каналы и настроенная скидка |
| Golden | `0` | Общедоступные каналы, скидка 3% после назначения |
| Bronze | `0` | Общедоступные каналы и настроенная скидка |
| Участник | `0` | Общедоступные каналы; назначается новым людям и людям при настройке, без удаления прежних ролей |

`0` означает отсутствие дополнительных глобальных прав у роли; доступ даётся в создаваемой структуре каналов. Обычным участникам в публичных каналах разрешены ViewChannel, ReadMessageHistory, UseApplicationCommands. В чатах добавлены SendMessages, AttachFiles, EmbedLinks, AddReactions. В голосовых — Connect, Speak, UseVAD, Stream. В информационных каналах запрещены отправка сообщений, создание веток и сообщения в ветках. В статистике запрещён Connect. Seller/Manager не получают глобальных ManageChannels, ManageRoles или ManageGuild. В тикетах у самого бота также разрешён MentionEveryone для единственного уведомления неменшнабельной роли Seller; allowedMentions ограничивает его точным ID Seller. В остальных сообщениях все уведомления отключены.

Все приватные области сразу создаются с deny ViewChannel для `@everyone`. Тикет доступен автору, явно добавленным участникам, Seller, Manager, Admin и боту. Закрытый тикет сохраняет чтение для покупателя, но запрещает отправку. «Участник» не получает разрешающих overwrites в приватных областях. Developer, Sponsor, Partner и покупательские ранги не видят чужие тикеты и админку.

Технические журналы «антикраш» и roles: Admin/Developer. Журналы заявок, халявы, тикетов: Admin/Seller/Manager. Join-leave, набор, message и moderator-only: Admin/Manager. Остальные служебные роли в них не включены. Бот пишет журналы; moderator-only доступен для рабочего общения. Админка — только Admin и бот.

Administrator и реальный владелец сервера имеют доступ в соответствии с моделью Discord. `hoist=false` убирает отдельную группу в списке участников, но не скрывает роль в профиле или API. Administrator не отменяет иерархию ролей и не делает пользователя владельцем сервера.

После настройки можно убрать Administrator у бота. Для обычной работы оставьте ViewChannel, ReadMessageHistory, SendMessages, AttachFiles, EmbedLinks, ManageChannels, ManageRoles и ManageMessages; роль бота должна оставаться выше ролей магазина. При полном повторном setup/repair снова нужен Administrator для создания/обновления служебной Admin; без него бот сообщит о недостающем праве. Сам себе бот права не выдаёт. Не изменяются разрешения чужих каналов.

## Каталог, цены и скидки

Стартовые данные — `config/catalog.seed.json`, импортируются **один раз** в SQLite. Категории Genshin Impact, Telegram, Discord, Honkai Star Rail, Zenless Zone Zero уже добавлены. В Discord есть Nitro и украшения профиля; эффект профиля удалён. До заполнения цен, наличия и условий варианты доступны для просмотра, но купить их нельзя.

- `/category id:discord` — визуальная панель для названия, описания, эмодзи, порядка и публикации категории.
- `/product id:nitro` — визуальная панель для текста, категории, изображения, цены, наличия, условий и вариантов товара.
- `/product id:decoration` — настройка украшений профиля и цен каждого номинала.
- `/discount role:@Golden percent:3` — скидка по ID роли; при нескольких ролях применяется максимальная.
- `/rank user:@покупатель rank:golden` — только Admin/владелец; допускаются лишь Bronze, Golden, Diamond. Другие роли сохраняются, прежний покупательский ранг снимается.

Пример доступного товара (коммерческие данные заполните самостоятельно): `price` — **целое количество минимальных единиц валюты**, для RUB это копейки. `available: true`, `enabled: true`, `terms` не пустое. Для вариантов нужны `id`, `name`, `price`, `available`; до 25 вариантов. У товара с вариантами используется цена выбранного варианта. `delivery` — `usual` либо `subscriptions`, общие сроки берутся из `shop.json`. Используйте валюты с двумя дробными знаками (RUB, USD, EUR и т. п.). Скидка округляется до ближайшей минимальной единицы, половина вверх.

Nitro открывается так: **Discord → Discord Nitro → Full / Basic → Входом / Гифтом**. Группы заданы в `variantGroups` (`full`, `basic`), связь варианта с группой — поле `group`. Четыре варианта: `full-login`, `full-gift`, `basic-login`, `basic-gift`. В заказ сохраняются и тип Nitro, и способ получения. «Входом» — название способа получения; бот не собирает пароли, токены и коды входа.

У украшений 9 номиналов: **4.99$, 8.99$, 9.99$, 15.99$, 17.99$, 21.98$, 22.99$, 25.99$, 26.97$**. Это названия вариантов, а не цены продажи. В `/product id:decoration` выберите вариант из списка, нажмите «Название и цена» и введите обычную сумму в рублях, например `500` или `500,50`. Затем включите вариант, общее наличие товара и заполните условия. Для Nitro цены настраиваются так же, отдельно для каждого из четырёх вариантов.

Названия вариантов и цены меняются в визуальном редакторе. Структурные массовые изменения по-прежнему можно выполнить локальным импортом: пустые группы, неизвестные `group` и повторяющиеся ID не сохраняются. Обновление структуры Discord-каталога применяется один раз при запуске (`catalog.discordVariants.v1`); последующие изменения через команды сохраняются. Прежние записи каталога записаны в историю, снимки старых заказов не меняются. Для изменения уже работающего каталога используйте команды или импорт, а не редактирование seed-файла.

Максимум названия — 100 символов, описания товара — 800, условий — 500. HTTPS-изображения поддерживаются в карточках товара. Цена ограничена диапазоном 0…1 000 000 000 минимальных единиц. ID: латиница, цифры, `_`, `-`, до 40 символов. Форма JSON ограничена Discord 4000 символами; для большого каталога используйте локальный импорт:

```sh
# При остановленном боте. Формат файла тот же, что у catalog.seed.json.
npm run catalog:import -- config/my-catalog.json
npm run catalog:export -- data/catalog-export.json
```

Импорт обновляет только перечисленные ID, не удаляет остальные. Каталог и визуальные редакторы доступны Seller и Admin; скидки и ранги — Admin. Настройки сохраняются в SQLite и переживают перезапуск.

Автоматическое повышение включается только после заполнения `ranks.thresholds` в **минимальных единицах**, отдельно для `bronze`, `golden`, `diamond`. Суммы учитываются в `ranks.currency`; валюты не складываются и не конвертируются. Одна завершённая покупка учитывается один раз. По умолчанию порогов нет; скидки Bronze/Diamond не заданы. При ручной смене ранга сумма покупок не сбрасывается.

## Заказы, тикеты и поддержка

Публичное меню открывает приватный каталог, не меняя общую панель. Списки товаров/категорий разбиты по 25 позиций. Оформление: категория → товар → вариант → итог → комментарий → подтверждение. Сессии принадлежат пользователю и действуют `tickets.sessionMinutes` минут. Перед созданием заново проверяются цена, наличие и актуальные роли; изменение условий требует повторного подтверждения.

После подтверждения создаются снимок заказа и приватный канал `⏳-имя-000123`. `/support` и кнопка поддержки открывают форму темы/описания и канал `support-имя-000124`. Номер общий для всех тикетов. `tickets.activePerType` по умолчанию 1; задержка — `tickets.cooldownSeconds`. Повторный запрос возвращает существующий тикет.

Кнопки тикета: принять, закрыть, архив; после закрытия — открыть снова и удалить. Автор может закрыть свой тикет через форму подтверждения с причиной. Остальное — Seller/Manager/Admin. `/ticket id:123 action:add user:@участник` и `action:remove` управляют дополнительными участниками. Доступ сотрудника определяется ролью.

Финансовые действия: **Ожидает оплаты → Оплачен → В работе → Выполнен**, либо Отменён. Доступны Seller/Admin. Для отмены после оплаты обязательны причина и результат ручного урегулирования. Возврат автоматически не подтверждается. Закрытие тикета не меняет финансовый статус. Скриншот оплаты и сообщения покупателя сами статус не меняют.

Способы оплаты — `paymentInstructions`. По умолчанию: «Способ оплаты согласует продавец». Бот не покупает и не активирует товары через выдуманные API, не запрашивает пароли, Discord-токены и коды входа.

Перед закрытием/удалением сохраняется TXT-архив с авторами, временем, доступным содержимым и **ссылками на вложения**. Сами вложения не скачиваются; ссылки могут истечь — это указано и в каждом архиве. Архив разбивается на части и направляется только в закрытый журнал тикетов. Если сохранение не удалось, канал не закрывается/не удаляется. Message Content Intent необходим для полного доступного текста; удалённые сообщения бот не восстанавливает. Если этот intent отключён в Developer Portal при включённом запросе клиента, Discord может отклонить подключение — включите intent, а не считайте пустой архив полным.

`/myorders` показывает только свои заказы; `/order` — сотрудникам. Перезапуск восстанавливает управление через общий маршрутизатор и сохранённые ID. Ручное удаление канала снимает его с активных тикетов; заказы остаются в истории.

## Розыгрыши, отзывы, статистика

Кнопка «🎁 Розыгрыш» в панели создания тикетов предназначена для получения уже выигранного приза. Победитель вставляет ссылку на сообщение Discord о выигрыше, после чего бот создаёт отдельный приватный тикет «Выдача выигрыша». Такой тикет не занимает лимит обычной поддержки.

Кнопка «Розыгрыш» открывает модальную форму ссылки на сообщение Discord. Бот проверяет только официальный Discord URL и доступность сообщения через Discord API. Недоступная ссылка передаётся на ручную проверку. Одна ссылка от одного пользователя создаёт одну заявку. Сотрудники одобряют участие либо отклоняют с причиной. Пользователь получает результат в DM, а при закрытых DM видит его через `/giveaway`. Определение победителей и выдача призов не реализуются в этой версии.

Отзывы публикуются людьми обычными сообщениями в канале отзывов. Писать могут владельцы рангов Bronze, Golden и Diamond; сообщения остальных участников удаляются. Бот учитывает подходящее сообщение в статистике и ставит реакцию ⭐. `/review order:123 action:remove` доступна Admin/Manager для старых импортированных отзывов и требует причину. `/review order:123 action:import message:ID` — Admin; сообщение должно существовать в канале отзывов, его автор должен совпадать с покупателем выполненного заказа.

Счётчик отзывов считает только опубликованные записи из БД, связанные с сообщениями. Одиночное/массовое удаление и сверка после запуска снимают удалённые сообщения с подсчёта. Ошибка доступа не считается удалением.

Состав участников берётся полным запросом, не из неполного кэша. По умолчанию боты исключены (`statistics.includeBots`). Сверка и применение переименований — не чаще `statistics.intervalMinutes`, минимум 10 минут. При неизменном значении запрос переименования не отправляется. Проверенные значения и времена сохраняются в БД; после ошибки они остаются прежними, владелец получает уведомление. `status` и `/diagnostics` показывают состояние.

## Журналы и хранение

События журналов публикуются единообразными цветными блоками: тип события, участник или роль через нативное упоминание Discord, понятные поля и время события. В журнале ролей автор изменения определяется через аудит Discord; боту нужно право «Просмотр журнала аудита». Упоминания в журналах не отправляют уведомления. Технический журнал не выводит токены, тела запросов и пользовательские секреты.

`data/shop.sqlite` содержит настройки, ресурсы, ID панелей, каталог, сессии, заказы, тикеты, заявки, отзывы, историю и очередь уведомлений. Миграции — `migrations/*.sql`, применяются автоматически при запуске. Скопируйте SQLite и WAL/SHM согласованно либо остановите бота перед резервным копированием. Не публикуйте БД и `.env`: в БД находятся сообщения обращений и коммерческая история.

Подключены join-leave, roles, тикеты/архивы, заявки, изменения/удаления сообщений публичных чатов, технические ошибки. Личные тикеты и админка не копируются в message. Кто удалил сообщение, бот не угадывает. Содержимое технических ошибок не включает тела Discord-запросов, токены и данные форм. «Антикраш» — название технического журнала, а не обещание автоматической защиты. «Набор» и журнал халявы подготовлены для будущих модулей. Кейсы — информационный канал без придуманной механики.

Очередь уведомлений повторяет неудачные отправки после запуска. Пока канал журнала не создан, его записи тихо ожидают настройки и не блокируют остальные задачи. Ошибка доставки в настроенный журнал откладывает повтор для этого журнала на пять минут; записи сохраняются, а предупреждение выводится один раз на попытку. Уведомление роли в новом тикете отправляется не более одного раза; в случае сбоя сразу после записи флага уведомление может быть пропущено, но не отправлено повторно. Для обычных уведомлений после редкого сбоя между отправкой и подтверждением возможна повторная доставка; бизнес-операция и начисление суммы при этом не повторяются.

## Проверка

```sh
npm run check
npm test
npm run validate
npm run build
```

Тесты используют реальную локальную SQLite и подменённый Discord API: скидки/округление, повторные действия, права по ID, приватные overwrites, привязку сессий к пользователю, сохранение после перезапуска, отказ удаления при ошибке архива, заявки, отзывы, статистику, повторную публикацию и замену баннера. `validate` собирает все 21 панели и проверяет ограничения Components V2 без подключения к Discord.

**Полный цикл работы на настоящем сервере Discord ещё не подтверждён.** При диагностике настройки через API проверены роли бота и владельца; исправленная расстановка ролей применена и подтверждена на сервере. Полная настройка каналов и сценарий заказа требуют отдельной проверки. После исправления иерархии проверьте приглашение, hierarchy, DM-команду, видимость каналов с тестовым покупателем/Manager/Developer, полный цикл заказа, закрытие/архив и замену баннера. Точные размеры, фон и шрифт определяет клиент Discord.

## Структура исходников

- `src/core` — конфигурация, SQLite/миграции, Components V2, права.
- `src/modules/panels.ts` — информация, правила, каталог и остальные публичные панели.
- `src/modules/setup.ts` — строго ограниченная DM-настройка и восстановление ресурсов.
- `src/modules/catalog.ts`, `orders.ts`, `tickets.ts` — каталог, скидки/снимки, обращения и архивирование.
- `src/modules/giveaways.ts`, `reviews.ts`, `statistics.ts`, `roles.ts`, `logs.ts` — остальные модули.
- `src/router.ts` — постоянные обработчики кнопок, форм, меню и команд.
- `src/index.ts` — подключение, события и фоновые задачи.
- `src/register.ts` — отдельная регистрация slash-команд.
